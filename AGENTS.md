# Capy Print — руководство для агентов

Инструкции распространяются на весь репозиторий. Перед изменениями прочитайте этот файл, проверьте состояние Git и изучите затрагиваемый сценарий целиком.

## Назначение проекта

Capy Print — приложение копицентра для заказа печати документов и фотографий. Клиент загружает файлы, выбирает бумагу, цветность, количество копий, двустороннюю печать и срок выполнения. Сотрудник управляет заказами и статусами; клиент получает сообщение о готовности.

Сейчас реализована интеграция с Telegram Mini Apps. Приоритет развития — запуск того же приложения во VK Mini Apps с сообщениями от сообщества VK, затем обновление UI/UX. План и критерии приёмки: [docs/vk-mini-apps-ui-ux/README.md](docs/vk-mini-apps-ui-ux/README.md).

Оплата при получении описана в текущем FAQ бота. Онлайн-оплата, расчёт стоимости, VK, промокоды и реферальная программа пока не реализованы. Не описывайте запланированные функции как доступные пользователю.

## Стек

- Next.js 16, App Router, React 19, TypeScript со strict-режимом.
- Mantine 8 и Tailwind CSS 4 для интерфейса; Lucide для иконок.
- React Hook Form и Zod для клиентских форм.
- TanStack Query и Axios для клиентских запросов.
- PostgreSQL, Prisma 7 и PostgreSQL adapter для базы.
- UploadThing для загрузки файлов.
- `@tma.js/sdk-react` для Telegram Mini Apps.
- Telegram Bot API вызывается через Axios; наличие `grammy` в зависимостях не означает, что webhook построен на нём.

Текущие env: `DATABASE_URL`, `TELEGRAM_BOT_TOKEN`, `ADMIN_GROUP_CHAT_ID`, `UPLOADTHING_TOKEN`, `NEXT_PUBLIC_BASE_URL`, `NEXT_PUBLIC_MINI_APP_URL`. Не выводите значения токенов, URL базы с паролем, полные `.env` или сырые данные авторизации в логи и ответы. `.env*` игнорируются Git. Только публичные настройки получают префикс `NEXT_PUBLIC_`.

## Правила изменения кода

- Сначала проверьте `git status`. Сохраняйте несвязанные изменения пользователя; не откатывайте их ради задачи.
- Держите изменения в пределах запроса. Не смешивайте интеграцию VK с массовым редизайном.
- Сохраняйте существующее поведение Telegram при введении платформенных адаптеров.
- Используйте TypeScript, существующие компоненты и стиль соседних файлов. Новую зависимость добавляйте, когда она решает конкретную задачу.
- SDK платформ, DOM и browser storage используйте только на клиенте. Секреты, проверка подписей, Prisma и отправка сообщений остаются на сервере.
- Проверяйте входные данные и права на сервере. Клиентская Zod-схема и скрытая кнопка не заменяют серверную проверку.
- Пользователь для создания и чтения заказов должен определяться проверенной авторизацией. Переданный клиентом ID не является подтверждением личности.
- Для доступа к заказу проверяйте владельца или роль ADMIN. Не предоставляйте клиенту общий административный список.
- Идентификаторы внешних платформ не смешивайте с внутренним `User.id`. Не объединяйте аккаунты по имени, username или совпадению числового ID.
- Учитывайте BigInt при ответах API: используйте согласованную сериализацию и JSON-типы, а не прямой JSON.stringify модели Prisma.
- Изменения БД оформляйте миграциями с сохранением данных. Не переписывайте применённые миграции и не используйте reset/db:push как способ выпуска изменений в production.
- Перед выполнением команды, меняющей БД, выясните целевое окружение. Не запускайте миграции на неизвестной или production-базе как часть обычной проверки.
- Обновляйте env-документацию, карту проекта и план, если меняется архитектура или статус задачи.
- Не публикуйте приложение, не отправляйте реальные тестовые сообщения и не меняйте настройки внешних сервисов без соответствующего поручения.

## Известные ограничения текущей реализации

Это задачи для исправления, а не образцы архитектуры:

- Для сессий нужны миграции `20261003000000_mini_app_sessions` и `20261003010000_persistent_sessions`; к текущей базе они пока не применены. Bearer с префиксом vk_/telegram_ хранится только в памяти и действует до отзыва. После reload со старыми/потерянными launch params нужно заново открыть Mini App. Нативные VK/Telegram клиенты ещё не проверены.
- Telegram webhook не проверяет secret token. Upload middleware уже требует серверную сессию и проверяет MIME.
- `User.telegramId` остаётся nullable переходным полем Telegram-уведомлений; аккаунты Telegram/VK разделены через UserIdentity. VK Bridge и VKWebAppInit подключены; профиль VK, темы/платформенные действия и сообщения от сообщества ещё не реализованы.
- Отправка клиентских сообщений встроена в обработчик изменения заказа; ошибка отправки не сохраняется для повторения.
- Расписание в боте и форме расходится. При унификации требуется подтвердить реальные часы копицентра.
- `deadlineAt` хранится как String; POST/PATCH проверяют дату и сохраняют строку.

## UI/UX

- Пользовательские тексты — на русском. Сохраняйте узнаваемость капибары и зелёной палитры.
- Основной сценарий — телефон в WebView Telegram/VK. Проверяйте маленький экран, клавиатуру, safe areas, темы и кнопку назад.
- Показывайте состояния загрузки, ошибку с понятным восстановлением, пустой список и успешное завершение.
- Не показывайте фиктивные цены, сроки, скидки, гарантии удаления файлов или автоматические проверки, которых ещё нет.
- Анимации короткие, не мешают работе с формой, учитывают `prefers-reduced-motion`. Не анимируйте каждый элемент и не добавляйте библиотеку только ради hover.
- Используйте корректные label, доступный контраст и управление с клавиатуры. При переходах между шагами сохраняйте введённые данные.

## Проверка и завершение задачи

После изменений кода выполняйте проверки соразмерно задаче: TypeScript, ESLint затронутых файлов, build при изменении интеграции/сборки. Не добавляйте бессодержательные тесты на документацию или косметические изменения.

Для авторизации, миграций и уведомлений нужны проверки поведения: неверная/просроченная подпись, чужой заказ, сохранение существующих данных, отказ в сообщениях, ошибка доставки, отсутствие дублей. `npm test` проверяет launch data и HTTP-контракт авторизации; остальные сценарии добавляйте при реализации соответствующих этапов. Выбранный способ проверки документируйте.

Для интерфейса проверьте затронутый сценарий в браузере; тест в обычном браузере не подтверждает работу нативного Bridge. Для платформенных изменений требуется проверка внутри Telegram/VK.

При сдаче укажите, что изменилось, что проверено и что ещё зависит от внешних настроек. Для изменений только документации достаточно проверки ссылок, путей и diff. Не коммитьте и не отправляйте изменения в remote без поручения пользователя.
