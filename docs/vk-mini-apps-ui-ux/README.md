# План: VK Mini Apps и обновление UI/UX Capy Print

Дополнение от 9 октября 2026: добавлены запрос разрешения сообщений сообщества в интерфейсе VK, серверная проверка разрешения и сообщения при PRINTING/COMPLETED/CANCELLED. Код проверяется без базы и Docker; настройки сообщества и нативная проверка остаются открытыми. [Настройка и ограничения уведомлений](notifications.md).

По замечаниям к diff разрешение перенесено в единый диалог при первом входе. Выбор сохраняется в VK identity; после согласия или отказа повторного диалога нет. Подготовлена новая миграция `20261009000000_vk_messages_preference`, к базе она не применена.

Добавлены дубликаты новых заказов сотрудникам VK: `VK_ADMIN_PEER_IDS` задаёт получателей через запятую, Telegram и каждый VK peer отправляются независимо. Общая функция сохраняет одинаковые сведения и ссылки заказа, учитывая HTML Telegram и обычный текст VK. Ошибки Telegram теперь включают безопасный транспортный код и таймаут. [Настройка дубликатов](notifications.md#дубликаты-новых-заказов-сотрудникам).

Исправления запуска от 9 октября 2026: reload без launch query использует окружение iframe/WebView и `VKWebAppGetLaunchParams` с прежней серверной проверкой подписи/времени; автоматические запросы ограничены 10 секундами с возможностью повтора. Разрешение сообщений использует `supportsAsync`, нативный выбор пользователя не ограничен таймаутом. Старые launch params всё ещё требуют повторного открытия Mini App. [Подробности проверки](authentication.md#повторная-сверка-vk--9-октября-2026).

Дополнение от 8 октября 2026: реализованы получение профиля VK через Bridge и сохранение в существующий User, платформа/ID/контактные ссылки в уведомлении сотрудникам и деталях заказа. После создания заказа обновляется клиентская история; ошибки загрузки отображаются отдельно от пустого списка. Подробности, проверки и ограничения: [исправления профиля и заказов](authentication.md#исправления-профиля-и-заказов--8-октября-2026).

Статус: реализованы серверные сессии Telegram/VK и перевод API на них; актуальная документация VK сверена в браузере. Миграция подготовлена, к текущей базе не применена. Проверки в настоящих iframe/WebView остаются открытыми. Обновлено 3 октября 2026 года. Дата создания: 30 сентября 2026 года. Рабочая ветка: `feature/connect-vk-mini-apps`.

## Цель и порядок

1. Запустить существующий Capy Print во VK Mini Apps: файлы, оформление, история и управление заказами.
2. Отправлять клиенту сообщение о готовности от сообщества VK, аналогично Telegram-боту.
3. Обновить главную, страницу заказа, экран результата и добавить умеренные анимации.

Промокоды, рефералка, бонусная программа, онлайн-оплата и большой каталог новых товаров — отдельные последующие задачи. Они не входят в первый релиз VK.

## Что уже есть

- Next.js frontend и backend в одном проекте, PostgreSQL через Prisma.
- Общий MiniAppProvider/useMiniApp, адаптеры Telegram SDK и VK Bridge; пользователь и роль из серверной сессии.
- Двухшаговая форма: файлы/параметры, затем срок/комментарий.
- Загрузка в UploadThing; наборы печати с несколькими файлами.
- История клиента и административные страницы.
- Telegram-бот с меню и справочной информацией.
- Уведомление о новом заказе в административный Telegram-чат и дубликаты сотрудникам VK из env.
- Сообщения клиенту при статусах PRINTING, COMPLETED и CANCELLED.

Серверные VK identities и сессии уже реализованы; `x-telegram-id` больше не используется для авторизации. VK Bridge подключён для VKWebAppInit, получения профиля и запроса сообщений сообщества. Уведомления о статусе отправляются общим сервисом в Telegram/VK. Темы/платформенные действия и VK Callback API ещё не реализованы. Результат повторной сверки и открытые проверки: [аудит интеграции](authentication.md#повторная-сверка-vk--9-октября-2026); настройки сообщений: [уведомления](notifications.md#настройки-владельца).

Результат этапа: [контракт, env, алгоритмы, тесты и ограничения](authentication.md). `POST /api/auth/session` проверяет исходные launch data, разрешает identity и выдаёт бессрочный случайный Bearer с префиксом vk_/telegram_; в БД хранится хеш. GET читает текущего пользователя/роль, DELETE отзывает токен. Заказы, пользовательский API и UploadThing используют сессию; legacy upsert отключён. Проверка подписи/app ID/vk_ts сверена непосредственно с порталом VK 03.10.2026. SQL-миграция проверяется на отдельном PostgreSQL WASM в памяти, маршруты — на заглушках Prisma без сети/реальных сообщений. Текущая база не изменялась. Результаты локальных проверок и открытая матрица нативных клиентов описаны в контракте.

Реализованная модель — внутренний User и отдельные внешние аккаунты. В первом релизе разные платформы создают разные аккаунты; автоматического объединения нет. Роль ADMIN назначается отдельно и не переносится по совпадению имён.

На следующем этапе заказ должен сохранять платформу/identity, из которой создан, чтобы выбирать канал уведомления даже при будущем связывании аккаунтов. Сейчас платформа есть у identity сессии, отдельного поля в заказе ещё нет; VK-уведомления не реализованы.

### 5. Настройки окружения

Шаблон окружения: [env.example](../../env.example). Все значения в шаблоне пустые; настройки будущих этапов VK отмечены комментариями.

Существующие переменные:

| Переменная                 | Использование                                                         |
| -------------------------- | --------------------------------------------------------------------- |
| `DATABASE_URL`             | PostgreSQL; только сервер                                             |
| `TELEGRAM_BOT_TOKEN`       | Telegram Bot API и проверка Telegram initData; только сервер          |
| `ADMIN_GROUP_CHAT_ID`      | Административный Telegram-чат                                         |
| `UPLOADTHING_TOKEN`        | UploadThing; только сервер                                            |
| `NEXT_PUBLIC_BASE_URL`     | Базовый URL клиентских API                                            |
| `NEXT_PUBLIC_MINI_APP_URL` | Текущий URL Telegram Mini App в меню бота                             |
| `VK_APP_ID`                | Ожидаемое приложение при проверке launch params                       |
| `VK_APP_SECRET`            | Секрет приложения для проверки подписи; только сервер                 |
| `VK_GROUP_ID`              | ID сообщества для разрешения и отправки сообщений                     |
| `VK_GROUP_TOKEN`           | Токен этого сообщества с правом messages; только сервер               |
| `VK_ADMIN_PEER_IDS`        | Получатели служебных копий новых заказов через запятую; только сервер |

Планируемые переменные, ещё не подключены к коду:

| Переменная                 | Использование                                      |
| -------------------------- | -------------------------------------------------- |
| `VK_CALLBACK_SECRET`       | Проверка callback-запросов; только сервер          |
| `VK_CALLBACK_CONFIRMATION` | Код подтверждения callback endpoint; только сервер |
| `TELEGRAM_WEBHOOK_SECRET`  | Проверка заголовка секретного токена webhook       |

Публичные ID для Bridge отдавать через конфигурацию либо отдельные `NEXT_PUBLIC_*` переменные. Секреты всегда остаются на сервере. Ссылки открытия VK Mini App и параметры окружений документировать после регистрации приложения. Для отправки от сообщества нужен его токен; сервисный токен приложения не заменяет его.

`SESSION_SECRET` не требуется: выбраны непрозрачные случайные токены с серверным хранением хешей. Перед выпуском нужна миграция сессий; её применение к текущей базе отложено по указанию пользователя.
